### 검증 격리와 재실행

실행 중인 서버와 간섭하지 않도록 `project2_loadtest` DB 안에 `loadtest_app` 소유의 `regression_20260909` 스키마를 별도로 만들었다. 이 스키마만 최초 `update`로 준비했으며 PostGIS·pgvector는 기존 `public` 확장을 사용했다. Redis는 비어 있음을 확인한 DB 15를 사용했다. 서버의 `loadtest` 스키마와 Redis DB 0, 개발·운영 DB에는 테스트를 실행하지 않았다. 회귀 테스트 스키마는 재실행을 위해 보존한다.

이미 생성된 테스트 스키마로 재실행하려면 프로젝트 루트의 **별도 PowerShell 창**에서 다음을 실행한다. 창을 닫으면 해당 환경변수 설정도 종료된다. 이 설정은 서버 실행용 IntelliJ 설정에 추가하지 않는다.

```powershell
$env:SPRING_PROFILES_ACTIVE = 'loadtest'
$env:SPRING_CONFIG_IMPORT = 'file:./performance/.env.loadtest[.properties]'
$env:SPRING_APPLICATION_JSON = '{"spring":{"datasource":{"url":"jdbc:postgresql://127.0.0.1:5433/project2_loadtest?currentSchema=regression_20260909,public"},"data":{"redis":{"database":15}},"jpa":{"hibernate":{"ddl-auto":"validate"},"properties":{"hibernate":{"default_schema":"regression_20260909","hbm2ddl":{"halt_on_error":true}}}}}}'
.\gradlew.bat compileJava test --rerun-tasks
```

보고서: `build/reports/tests/test/index.html`. 원본 결과: `build/test-results/test/`. 최종 실행 로그: Git 제외 경로 `performance/results/test-fix-full.log`. 과거 `test.log`는 최초 컴파일 실패 기록이다.
